Component theming guidelines

The guidelines, with an example under each point where one can be drawn. The examples are built from the theme files, the Timing set and the size tokens, so they change when the tokens do. Each example is a real theme drawn with its own tokens, named where it matters. Glass and the metal ring are approximations, not the real effects.

How this guidance stays true when a token changes

This guidance never contains a value of its own. A rule names the token it uses (alpha/dark/xs, radius/button, radius/border-width/md, Timing/fast, shadow, size-controls/interactive-component/min-height/component). A token whose name carries its size (alpha/blur/320/sm) is referred to by that name, which is how you named it. Where no token exists yet, the rule says what the number is for and a ? point asks for the token (see 11.1.4?). Because of that, changing a token's value in Figma changes the components and needs no edit here. If a rule ever does need a number, that is a missing token: it becomes a ? point, not text.

ALL COMPONENTS

1 Tokens

1.1 Theme tokens

1.1.1
Use theme tokens and styles only. Nothing is written by hand: no hex colour, no pixel radius, no shadow value, no duration.
  • Sizes and numbers: every size or number is a dimensions token, directly or through another token set (edges, spacing, icons and size-controls are all dimensions steps in Figma). A component never has a number of its own.
1.1.2
Every token applied to a component starts from the theme's settings, where they apply.

Exampleradius=sharp means no border radius anywhere.

2 Texture & color-mode

2.1 Colour-mode

2.1.1
color-mode (light or dark) is one setting per theme, whether the theme is defined in Figma or generated in the app. It dictates which colour tokens a component uses, within a theme, and which glass style is used. There is no second light or dark setting.
2.1.2
Fabrik is color-mode=light, as in Figma. Laroc is color-mode=dark. The code follows Figma.

2.2 Texture

2.2.1
Solid texture: the card token with an alpha overlay. Dark colour-mode: alpha/dark/sm. Light colour-mode: alpha/light/md.
2.2.2
Gradient texture: a top-to-bottom gradient from the md alpha step to the lg alpha step. Dark colour-mode: alpha/dark/md to alpha/dark/lg. Light colour-mode: alpha/light/md to alpha/light/lg.
2.2.3
Glass texture: the Soft glass from the Glass sheet, in its dark or light tone to match the colour-mode. It is the component's base background layer, with no fill colour and no alpha wash under it, and it overrides any rule that clashes with it (see 3.1.2*).

3 Lines

3.1 Borders

3.1.1
The outer shell has a border of radius/border-width/md. Light colour-mode: alpha/dark/xs. Dark colour-mode: alpha/light/xs.
3.1.2*
Exceptions: a glass texture has no border, and a component whose border is part of its effect (the metal ring) keeps its own.
3.1.3
The border is centred on the edge, so it never takes space from the padding. Padding and corners are worked out without it.

3.2 Other lines

3.2.1
Every other line a component has uses the same colour rule as the border (3.1.1).

4 Corners

4.1 Corners

4.1.1
Controls and the elements inside a component (buttons, inputs, selects, tabs, the nav bar, menu rows, chips) wear the theme's radius/button step. The step resolves per theme radius: sharp is square, rounded is fully rounded.
4.1.2*
Exception to 4.1.1: cards and other surfaces are not fully rounded on a rounded theme. They follow the numbered edges steps (sm, md, lg, xl) for the theme's radius.
4.1.3
The outer corner of a component that contains elements is the inner corner plus the padding of the outer component. The border is not counted. A card follows the same rule: a card that contains a card, a picture or a control takes its corner from this sum. A card with nothing inside it that has a corner of its own is radius/md.

Examplea nav bar. Its tabs are radius/button, so the bar is that plus its padding.

Examplea card with a picture in it. The picture is radius/xs, so the card is that plus its padding.

4.1.4*
Exception: the outer corner never goes past the theme's maximum for the control, radius/button.

Exampleradius=sharp is always square, whatever the padding.

5 Spacing

5.1 Padding

5.1.1
A core interactive component's padding is at least size-controls/interactive-component/min-padding/component, and is always an even number.

5.1.2
An input field inside a component has double that component's padding at the sides.

5.1.3
A card's default padding is size-controls/card/padding/padding-md, and it is always an even number (5.1.1).

5.1.4
The theme's spacing setting drives layout between components only. Component padding stays at the fixed tokens (5.1.1, 11.1.1, 5.1.3), so a control is the same size in every theme. (Figma has mg for Amnesia's spacing, which looks like a typo for md.)

6 Icons

6.1 Icon

6.1.1
Use an icon from the Phosphor set, in the theme's selected icon weight, in a box of size-controls/interactive-component/min-height/icon-within-component by size-controls/interactive-component/min-width/icon-within-component (both resolve to icons/container/md).
Each icon sits in an icon-within-component box (outlined). The weight comes from the theme and is drawn by the app.
6.1.2*
Exception: a Figma file provides a different or unique icon.

7 Hover states

7.1 Hover

7.1.1
One formula based on colour-mode, for every texture. Light colour-mode: add alpha/dark/sm over the background. Dark colour-mode: add alpha/light/sm.
7.1.2
A state (hover, focus, press) only changes the background layer. It never changes the colour of text or an icon, a border, or a shadow.

COMPONENTS WITH POPUPS

A popup is a menu, popover or dropdown that a component opens.

11 Popups

11.1 Layout

11.1.1
Padding: at least spacing/padding/sm, always an even number.

11.1.2
Width: at least the system's minimum popup width, as a share of the width of the component that opens it (see 11.1.4?).

The popup is at least half the width of the component that opens it (never narrower than its own rows).

11.1.3
Corners: a popup is a card, so its corner is the card corner, radius/md (4.1.2, 4.1.3), and never the fully rounded control corner.
11.1.4?
The minimum popup width has no token. Should the share of the component's width become a token, and what should it be called?

11.2 Surface

11.2.1
Fill: the component's own fill (2.2) plus alpha/dark/sm on top. On a glass texture there is no wash, and the glass goes up one weight (the component's Soft is Medium in the popup, Medium is Heavy).
11.2.2
Blur: a heavy blur of what is behind it, from the alpha/blur variables at the sm step. A page narrower than the width in the name 1200 uses alpha/blur/320/sm; a page at least that wide uses alpha/blur/1200/sm.

Behind the popup: a paragraph of the page's own text, so the blur has something to soften.

12 Metal

12.1 Ring

12.1.1
On a light colour-mode, a metal ring sits on a darker line outside it, alpha/dark/xs, so the ring reads on a pale surface.

An illustration: the real effect is the metal-fx shader.

12.2 Fill and effect

12.2.1
The fill under the effect must be translucent, never solid white, or the effect can't be seen.
12.2.2
The effect must show and animate on every metal control, and metal controls shown together are the same height.
